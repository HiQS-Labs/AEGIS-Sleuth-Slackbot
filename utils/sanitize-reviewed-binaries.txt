# Binary (NUL-containing) files accepted after MANUAL review.
#
# Why this file exists
# --------------------
# `sanitize-scan.sh` runs its rules through `grep -I`, which treats a file containing NUL bytes as
# non-matching. A binary therefore can NEVER produce a finding regardless of what is inside it, so
# "no findings" on a binary means "not examined" — never "clean". The scanner enumerates such files
# and FAILS rather than letting silence imply safety.
#
# Most binaries should be removed from the tree, not listed here. This file is only for a *source*
# file that legitimately contains a NUL byte and must stay. Every entry needs a reviewer, a date,
# and what was checked — an entry without evidence is just a suppressed alarm.
#
# An empty or missing file means "nothing reviewed", which correctly keeps the gate closed.
#
# Format: one repo-relative path per line. Blank lines and #-comments ignored.
