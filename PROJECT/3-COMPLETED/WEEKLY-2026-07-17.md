# Weekly Shipped Report: July 10-17, 2026

Shipped to `main` from July 10, 2026 through July 17, 2026.

1. **Sleuth got much better at turning messy Slack threads into usable reminders.** It can now pull multiple proposed tasks out of a whole conversation, carry client and project identity forward, and surface proactive signals when work has gone quiet or starts aging badly.

   The net effect is less manual cleanup after the fact. More of the context survives the jump from chat into the reminder system.

2. **Reminder questions are a lot more trustworthy now.** `ask-reminders` moved toward deterministic filtering for time, client, user, and privacy before any model phrasing happens, and open results now render as real per-reminder messages you can act on.

   Reading the answer takes less work, and the command is less likely to hide the right task or show the wrong one.

3. **Reminder text now shows which client it belongs to.** A task in a client's channel reads with the client name up front instead of a bare, context-free line.

   That makes a busy digest easier to scan when several clients are in flight. The self-service half of this ticket — managing that list from a Slack List instead of a code deploy — shipped in the same release but landed inert: nothing pointed it at a real list, so no admin could actually use it yet. Wiring that up is a separate, still-unmerged change.

4. **Sleuth can now accept code-change requests from Slack and hand them off to Claude Code Cloud.** An admin can ask for a code task in Slack and get back a cloud session or PR path instead of manually relaying the request.

   That shortens the loop between “we should change this” and an actual code workflow starting. It's off by default and gated to one workspace for now, so this is a capability that exists, not something every admin can reach for yet.

5. **The first-responder router became more useful and easier to inspect.** Router mode can persist across restarts, the default model is pinned to a stable Flash Lite build, the `models` output explains what tier is active, and the router can optionally see a live workspace summary when deciding where to send a request.

   This makes routing behavior less opaque and less brittle. In active mode it can also answer some open-task count questions directly from live reminder data.

6. **Direct DM conversations finally work like they should.** You can message Sleuth one-on-one without an `@` mention or pre-existing thread, and follow-up replies in that DM now keep working instead of going quiet.

   That removes one of the roughest edges in normal day-to-day use. The DM path now behaves much more like people expect a chat assistant to behave.
